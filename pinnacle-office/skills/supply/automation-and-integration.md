# automation and integration

What the supply specialists in this seat have learned working on Pinnacle AI, a CBSE tutoring web app. This file exists so the next specialist doesn't re-discover the same platform quirks, dead APIs, and repo-specific gotchas from scratch.

- Upstash's REST API needs no persistent TCP connection (a normal client like ioredis fights connection pooling across ephemeral serverless/edge instances), and the free tier needs no card until an explicit upgrade — no accidental-billing risk from wiring it in.
- Government/NCERT-style scanned-image PDFs (common for NeGD/DLA docs) return empty or garbage text from pdftotext/pdfplumber — they only read the embedded text layer, no OCR. Tesseract or equivalent is a required separate step, not a config fix.
- @sylphx/pdf-reader-mcp ships a native Rust binary per platform as an npm optionalDependency and fails closed without a matching one (needs Windows x64 here); installing it is a `claude mcp add` registration, not something the office's restricted Bash allowlist (npm run build / npx tsc / node scripts/* / git) can do. It has now been recommended and independently flagged unverified three separate times — treat any future reliance on it as needing its own registry/GitHub check, not as settled.
- tesseract.js defaults to fetching its WASM core and traineddata from cdn.jsdelivr.net at runtime — fine for a one-off script, but anything student-facing needs corePath/langPath/workerPath pinned to local files instead.
- pdf-to-png-converter dropped its native `canvas` dependency as of v3.5+ and is pure JS on pdfjs-dist now, zero native/optional binaries — corrects an earlier belief that it shipped per-platform native binaries, which was only true of an older major version.
- WebFetch can't extract text from a PDF URL directly (returns raw binary to its summarizer), but it silently saves the fetched binary to a local tool-results path even on failure — that saved path is readable via readdoc. Use this when a PDF sits behind a URL and there's no curl/wget in the allowlist.
- DPDP Rules 2025 Rule 10 is three independent, equally valid verification routes, not one mandated method: (a) reliable details the fiduciary already holds, (b)(i) parent self-declaration, (b)(ii) a virtual token from an authorised entity (DigiLocker is one example, not the only one). Any single route suffices.
- Filing a Supply request auto-spawns a same-day research report titled after the request text in reports/<today>/ — check there for a title match before assuming a ticket is unanswered.
- The 2026-27 NCF-2023 rewrite is Class 9 only this year; Class 10 Maths/Science/English were verified byte-for-byte identical to what's already coded — NCERT deferred the Class 10/11 rewrite to 2027-28.
- The "Acad-14/2026" circular number cited in a brief doesn't exist; the real live one is 49_Circular_2026.pdf, a scanned/image PDF this environment cannot extract text from at all (no pdftoppm installed) — needs an OCR-capable tool, not WebFetch or Read.
- GitHub Models (models.github.ai) was fully retired 2026-07-30 for every customer — playground, catalog, inference API, and BYOK all gone, not a free-tier-only cutback. Any GITHUB_MODELS_TOKEN or `github` provider reference left in code is dead code. GitHub's changelog doesn't document what error old API calls now get (timeout/404/410) — confirm with a live curl before assuming the failure mode.
- Cerebras's deprecation table (inference-docs.cerebras.ai/support/deprecation) gives per-model dates and named replacements directly — check it instead of guessing. llama-3.3-70b and qwen-3-32b were deprecated 2026-02-16, replacement GPT OSS 120B, yet api/_llm.ts's DEFAULT_MODEL.cerebras is still hardcoded to llama-3.3-70b (live bug, unrelated to whatever task surfaces it). Cerebras's /models page currently lists only 3 active ids (gpt-oss-120b production; gemma-4-31b, zai-glm-4.7 preview) — spot-check any hardcoded id against it.
- Don't conflate Cerebras's two separate "Aug 17, 2026" claims: the pricing page's date is a footnote on one Preview model's deprecation, not free-tier or billing terms. The separate claim that a card will be required from that date traces to a single unverifiable paywalled X post quoting an alleged Cerebras email — no Cerebras-owned page corroborates it.
- Google's deprecations page (ai.google.dev/gemini-api/docs/deprecations) names the exact recommended replacement per deprecated Gemini model id directly — check it instead of guessing. gemini-2.0-flash/-001/-lite/-lite-001 are all 404 as of 2026-06-01 (any file hardcoding one is dead code); gemini-2.5-flash still works and is free-tier but shuts down 2026-10-16; current GA line is gemini-3.5-flash/gemini-3.6-flash, with gemini-3-flash-preview as bleeding edge.
- WebFetch's small summarizer model can misreport free-tier/pricing details even on pages that do have the data — cross-check with a second, differently-scoped fetch before trusting one summary on anything load-bearing. Its 15-minute response cache is also keyed loosely enough to return a stale in-progress snapshot when polling a slow endpoint (e.g. SSL Labs' analyze) — append a throwaway query param to force a fresh fetch.
- typescript-eslint is now one meta-package bundling matching versions of the parser, plugin, utils, and typescript-estree — install that instead of the separate @typescript-eslint/parser + @typescript-eslint/eslint-plugin, which risks version skew.
- eslint-plugin-react-hooks v6+ pulls in a real dependency tree (@babel/core, @babel/parser, hermes-parser, zod, zod-validation-error) because it now bundles React Compiler analysis rules — still free, but a much heavier install than the package name suggests.
- ESLint 9 and 10 support flat config (eslint.config.js) only — eslintrc support was removed entirely at 9.0.0, no legacy fallback. eslint-plugin-react-refresh's default export has plain-object configs, but its named `reactRefresh` export's equivalents are functions you must call (`.recommended()`) — easy to misconfigure into something ESLint silently ignores. create-vite's official react-ts template no longer ships eslint.config.js at all — it ships Oxlint (_oxlintrc.json) by default now, so there's no upstream Vite+React+TS ESLint template to copy from. This repo has no CI workflow (.github/workflows is empty), so adding ESLint only runs wherever it's manually wired in.
- data.gov.in's bot protection blocks WebFetch on the main domain for every path tried, but the sibling subdomain smartcities.data.gov.in is not behind the same block. web.archive.org is fully unreachable to WebFetch too, so it's not a workaround for the 403. api.data.gov.in returns 404 (not 403) on a guessed endpoint but needs a registered api-key and a known resource ID.
- vercel.json has never had a crons block added (git log on the file shows only the baseline commit) — any keep-alive fix proposed elsewhere is still just a proposal, not deployed.
- `node -e '...'` does NOT match the 'node scripts/*' Bash allowlist pattern and triggers an approval prompt like any other blocked node execution — confirmed by running it, not inference. A fix needs either that specific approval granted, or the workaround pre-committed to scripts/ and pre-approved.
- ncert.nic.in's public textbook PDFs use opaque filenames unrelated to book/class/subject (Kaveri Class 9 English is iebe1ps.pdf) — the only reliable way to find the right one is a targeted WebSearch (e.g. 'site:ncert.nic.in Kaveri class 9'), not guessing a URL pattern from other known NCERT filenames.
- core/claude.mjs settingsFor() hard-denies Bash(curl:*) and Bash(vercel:*) in its deny list for every agent, code-write or not — no TOOLS.* grant can override a deny-list entry, so 'give Supply curl' or 'give Supply vercel CLI' requests are asking for something the office's own permission layer forbids by design, not something missing an approval.
- requests.json's 'answered' status is not the same as resolved-and-known: 6 entries already carry the readdoc answer verbatim but the file still lists them as open work items rather than closed, so a scan by status alone overstates how many distinct blockers remain.
- jeemain.nta.nic.in, neet.nta.nic.in and satsuite.collegeboard.org's landing/navigation pages block WebFetch with 403; cuet.nta.nic.in itself loads but its 'Information Bulletin' listing page is just links — you need to follow through to the actual cdnbbsr.s3waas.gov.in PDF URL (WebFetch on the listing page will report that URL back to you) and then download+readdoc that PDF directly.
