# CLI tools

What the supply specialists in this seat have learned working on Pinnacle AI. Most of this is about which external tools/APIs lie to you, which internal files hide real constraints, and which npm/AI-provider facts have already gone stale once.

- NVIDIA's NIM catalog is an ongoing rate-limited free tier (40 RPM, no expiry) since early 2025, not a burnable one-time credit pool — don't trust older blog posts describing it as a trial.
- Bundle-analysis tooling gotchas: rollup-plugin-visualizer v7 requires node>=22 (check `node --version` before wiring it in); Bundlephobia's API returned an implausible 303-byte gzip figure for html2canvas twice in a row (realistic min+gzip is 45-55 KB) — don't trust it at face value for that package.
- Third-party "NCERT solutions" aggregators (byjus, vedantu, tiwariacademy, selfstudys, educart, mycbseguide) mix pre- and post-rationalisation content with no labelling — trust the repo's own boardNotes/rationalisation comments over them when they conflict. ncert.nic.in/textbook.php is JS-rendered and returns nothing to WebFetch either, so it's not a fallback. Separately, @sylphx/pdf-reader-mcp needs node>=22.13.0, and even downloaded PDFs can't be read without poppler/pdftoppm (not installed, dead end until provisioned). The "read NCERT/NeGD PDFs" request has been filed at least twice under different ticket IDs — check reports/<date>/ before treating it as still open.
- registry.npmjs.org/<package> returns raw, authoritative package.json (license, engines) — npmjs.com's rendered page 403s to WebFetch. For packages with long histories (e.g. vitest) use the /latest suffix; the full multi-version doc is too large and gets silently truncated mid-JSON.
- MarkingSchemeReveal (src/components/ui.tsx:126) is shared by Chapter, Papers and Worksheets — one fix there covers all three. q.answer already renders through `<Markdown>` (ui.tsx:109); only q.text (question prompt) and examinerTip render raw.
- No Vercel CLI/API access exists in this repo's toolset — plan tier (Hobby vs Pro) can't be verified from inside the office. Hobby function memory is fixed at 2GB (not configurable down), and exceeding any usage limit pauses that resource for ~rest of the billing month with no metered billing option — a limit breach during exam week is a full outage, materially worse than the app's own 429 rate limiter.
- vitest 4.1.10 needs node ^20||^22||>=24 and vite ^6||^7||^8 — this repo's node v24.16.0 and vite ^8.1.4 clear it, so `npm install --save-dev vitest` needs no version pin.
- pinnacle-office has zero ESLint anywhere (no config, no dep, no lint script) — any lint recommendation starts from nothing.
- tsconfig.json's include is only ["src","api"] — pinnacle-office/core is outside tsc's reach even though `npm run build` runs `tsc --noEmit`; TypeScript being a devDependency doesn't mean core/ is type-checked.
- GitHub Models (the whole provider) was fully retired 2026-07-30 per GitHub's own changelog, total and permanent, no grace window for existing tokens — the 'github' entry in AI_PROVIDER_ORDER is dead weight.
- Groq: GROQ_FALLBACK_MODELS already runs 'openai/gpt-oss-120b' (api/_llm.ts:128) as the replacement for llama-3.3-70b-versatile (shuts down 2026-08-16). llama-3.1-8b-instant shares that shutdown date but has its own distinct replacement, openai/gpt-oss-20b — don't collapse both slots onto the 120b id. qwen/qwen3.6-27b is Groq's secondary alternate if gpt-oss-120b gets overloaded as everyone's default fallback.
- Cerebras's /models and /models/overview pages list only gpt-oss-120b as production — llama-3.3-70b is gone from the catalog entirely, so DEFAULT_MODEL.cerebras is already broken, not approaching a cliff. Cerebras's model id is bare 'gpt-oss-120b', not 'openai/gpt-oss-120b' — the Groq-style prefixed id fails here.
- Gemini's gemini-2.0-flash is already shut down (deprecated 2026-02-18, executed 2026-06-01 per Google's changelog). OpenRouter's meta-llama/llama-3.3-70b-instruct:free is live now but delisted its entire free Meta Llama tier for ~9 days in mid-to-late July 2026 before reappearing — volatile, worth watching, not worth an emergency swap today.
- WebFetch caps quoted excerpts at ~125 chars for legal/regulatory sources — chunk statute extraction across multiple requests. egazette.gov.in fails with a certificate error and indiacode.nic.in returns 403 — neither primary government source is reachable via WebFetch; private mirrors (dpdpact2023.com, dpdpa.in) agree with each other on wording but are not primary sources.
- Better Stack's monitor creation API needs monitor_type=expected_status_code + expected_status_codes (array, can include 403) + http_method=POST — the free plan (10 monitors, 3-minute checks) has no monitor-type or method restriction.
- npm install is absent from every TOOLS array in claude.mjs for every department — it isn't gated behind approval, it was simply never added to any allowlist. That's the real answer behind repeated "npm install permission" requests.
- supply.mjs's dedup only half-works: key() (line 45) guards requestTool() against duplicate incoming asks by comparing `what` text, but is never consulted in fulfil(). fulfil() (lines 71-83) writes to CATALOG unconditionally with a plain append, no read-and-check-for-existing-line step — differently-phrased duplicate requests both get fulfilled and both land in catalog.md.
- On Android Chrome (the real mobile target), speechSynthesis.getVoices() effectively returns one usable voice per locale, fixed by the phone's Google TTS settings and invisible to the app — rate and pitch are the only per-character levers reachable at all. There is also no way to capture or post-process speechSynthesis audio with the Web Audio API (no MediaStream, no captureStream, by spec) — any "add a filter" approach on top of native narration is a dead end; distinct timbres require replacing the TTS engine entirely.
- Supabase pausing on the free plan can't be prevented by any setting — the doc phrasing is soft ("low activity over 7 days", "a few requests a day is enough"), not a hard count, so there's nothing exact to alert on except "any traffic at all, roughly daily." The only official fix is upgrading to Pro (paid, out of scope).
- Turnstile: developers.cloudflare.com/turnstile/plans/ is the authoritative pricing source (cloudflare.com/products/turnstile/ and /plans/ are stub pages). Tokens are single-use with a 300s TTL, so server verification must happen inside the same request that consumes the token — it can't be cached or verified out of band. Cloudflare's docs never state block-vs-fail-open behavior for unsupported browsers (e.g. Android WebView, old browsers) — that has to be an explicit design decision on our side; fail-open is the right default, not a hard gate.
- No manifest.json, icon PNGs, or service worker exist anywhere in this repo — any PWA work is from-scratch, not a config tweak. vercel.json already rewrites everything except /api/* to /index.html for the SPA — the SW's navigateFallback must mirror that same boundary or Vercel/SW behavior diverges online vs offline.
- npm run build / npx vite build were both blocked by the approval gate in one session even though 'npm run build' is on Supply's allowed list — don't assume Supply's Bash allowlist is honoured without an explicit approval prompt; verify rather than relying on a stale dist/.
- DOMPurify's SAFE_FOR_XML option defaults to true, not false — advisory summaries that call SAFE_FOR_XML-related bugs 'non-default config' are wrong; treat any SAFE_FOR_XML advisory as applying to bare sanitize() calls unless the app explicitly sets SAFE_FOR_XML:false (this app doesn't).
- gh api is refused in this seat's toolset, so GitHub Security Advisory GraphQL queries aren't reachable; had to cross-reference WebSearch-indexed advisory URLs, github.com/advisories?query=, and osv.dev/list to triangulate a trustworthy advisory list, since any single WebFetch of a JS-heavy GitHub advisory page risks the underlying small model paraphrasing rather than quoting.
- No DOMPurify.setConfig(), addHook(), or any sanitize() config object exists anywhere in src/ as of 2026-08-04 — the app's DOMPurify usage is the simplest possible shape (3 bare calls), which is why almost every advisory (all the IN_PLACE/RETURN_DOM/USE_PROFILES/hook-mutation ones) is categorically inapplicable regardless of version.
- console.groq.com/docs/deprecations is the authoritative page for Groq shutdown dates — console.groq.com/docs/models does not mention deprecation dates at all, so check both if verifying a Groq model id.
- Groq's own recommended replacement for llama-3.3-70b-versatile is two options: openai/gpt-oss-120b (already in this repo's GROQ_FALLBACK_MODELS) or qwen/qwen3.6-27b (listed as preview-tier, pricier per-token) — gpt-oss-120b is the safer pick since it's already proven in this codebase's fallback slot.
- Cerebras's /models/overview page confirms gpt-oss-120b is the ONLY production model now, with a free-tier context cap of 65k tokens (vs 131k paid) — worth knowing if any lesson prompt is sized near that ceiling.
- Gemini 3.6 Flash has a genuine no-card free tier via AI Studio, but Google explicitly reserves the right to use free-tier prompts to improve its products — same trade-off DEFAULT_MODEL.gemini already implicitly accepted with 2.0 Flash, just flagging it's still true on the replacement.
