# design and asset sources

What the supply specialists in this seat have learned working on Pinnacle AI. Most pain here comes from two things: government/enterprise sites blocking automated fetch clients outright, and "free tier" providers changing terms or model availability out from under a hardcoded config.

- Government PDF hosts (egazette.gov.in, meity.gov.in, indiacode.nic.in) all 403 WebFetch on every path tried — confirmed independently twice, this is generic bot/WAF blocking, not dead or moved URLs. static.pib.gov.in is the one GoI host that isn't blocked, but only serves backgrounders, not gazetted text — don't expect it to close a "find the actual rule text" task.
- For DPDP Rules 2025 specifically: Rule 10 text has zero indexed .gov.in hits (crawlers are blocked too, not just this tool) — only dpdpa.com and law-firm blogs have it verbatim. The Gazette ID CG-DL-E-14112025-267650 (G.S.R. 846(E), 13 Nov 2025) is corroborated across multiple sources and is the right thing to hand a human to look up directly.
- NCERT PDFs (ncert.nic.in) are Photoshop-scanned page images, not text — WebFetch extracts nothing. Needs OCR/poppler, which isn't installed and Supply can't install. Third-party mirrors exist (toppersclan.com full-book PDF, Scribd IDs 999694136/1012778723) but the mirror exceeds WebFetch's 10MB cap and Scribd's preview hides body text.
- Piper TTS: original MIT repo archived late 2025, active dev moved to GPL-3.0 fork (piper1-gpl) — check which fork any npm wrapper (e.g. @mintplex-labs/piper-tts-web) actually bundles before calling it MIT.
- Proton Mail free tier has no SMTP/IMAP; Bridge is paid-only. Any "send mail programmatically from a Proton account" request is dead on arrival without a plan upgrade.
- [[supply_pdf_reader_mcp_unverified_flag]]: prefer tesseract.js+pdf-to-png-converter over @sylphx/pdf-reader-mcp (flagged unverified across 3 reports).
- [[supply_uptime_monitor_options]]: Better Stack is the current pick (UptimeRobot free plan bans commercial use since Dec 2024, Freshping is dead). Its dashboard form fields map 1:1 to API/Terraform params (http_method, request_headers, monitor_type, expected_status_codes, check_frequency) — no separate UI vocabulary. Must set monitor_type to expected_status_code, not default status (2XX-only) — that's the one step that would silently make a check for [[project_api_chat_health_check_pattern]] (expects 403) useless.
- LLM provider free tiers rot on independent, uncoordinated schedules — check the platform being live and the specific hardcoded model string separately, per provider, every time:
  - Cerebras retires its no-payment-method free tier 2026-08-17 (card required after); conflicts with this project's "free tier or open source, everywhere, forever" constraint — needs a founder call, not a config fix.
  - Groq's DEFAULT_MODEL (llama-3.3-70b-versatile) AND its listed fallback (llama-3.1-8b-instant) both decommission 2026-08-16 — only openai/gpt-oss-120b in the current fallback list survives that date.
  - GitHub Models shut down entirely 2026-07-30 (not a per-model deprecation) — the `github` provider block in api/_llm.ts is dead code.
  - OpenRouter free models vanish from api/v1/models with no announcement (confirmed meta-llama/llama-3.3-70b-instruct:free gone from the live endpoint) — the per-model web page can still show a stale "Free" listing after removal, so query the API, not the page.
  - Cerebras's deprecation table has no shutdown date column; cross-check /models/overview instead — absence from current prod/preview lineup means already pulled, not scheduled.
- Claude Code harness/permissions, confirmed live in this repo:
  - .claude/settings.json exists and is git-tracked, but only has an `env` block (stripping ANTHROPIC_API_KEY etc.) — no `permissions` block. A role-prompt instruction like "Bash, but only: npm run build, ..." does nothing on its own; npx tsc still prompted for approval despite being on that list, because npx runs arbitrary code the harness can't pre-verify as just the local binary.
  - Allow-rule syntax is `Bash(<prefix><wildcard>)` (e.g. `Bash(node scripts/*)`), wildcard only matches as a suffix — per code.claude.com/docs/en/settings.
  - Chained commands (`cmd1 && cmd2`, `cmd1; cmd2`) require approval even when every sub-command is individually allowlisted — run one script per Bash call, don't chain.
  - `.claude/settings.local.json` being auto-added to `.git/info/exclude` on creation is documented but unverified on this machine — the file has never existed here, so check `.git/info/exclude` after creating it, don't assume.
- pinnacle-office internals worth knowing before proposing a fix in this area:
  - `toolsFor()`'s isCodeWrite = (dept.kind==="code" && office.mode==="apply") — no per-task read-only/verification distinction; a verification-only QA/Tutor/Security task gets the same tools as an edit task.
  - `core/supply.mjs`'s BASE catalog string tells every department (including report-kind ones like Supply/UX/Finance/Legal) it has Bash/build/node access, regardless of dept.kind or office.mode — a capability toolsFor() can never actually grant those departments.
  - `claude.mjs`'s `runAgent()` closes stdin right after writing the prompt and only parses "system"/"assistant"/"result" events — any interactive permission request from the underlying CLI outside `--allowedTools` has no path to be answered and can only time out.
  - `state/` under pinnacle-office is read-denied to the Supply seat (SETTINGS deny list) — can't confirm live office.mode/task history from this seat; that check belongs to whoever owns chief.mjs.
  - `task.requestId` is only ever set by chief.mjs's own `raiseRequests()` (dept: "supply") — gating on `if (task.requestId)` alone is sufficient in report-kind code paths, no need for an extra `dept.key === "supply"` check.
- Turnstile tokens are single-use and expire in 300s, so wiring the widget directly into every /api/chat call (one per chat message) is a UX and architecture mistake — verify once, mint a server-signed pass, and check the pass on subsequent calls instead.
- No CSP header exists anywhere in this repo (checked vercel/netlify config and source), so adding challenges.cloudflare.com needs no allowlist change today — but if a CSP is ever added, script-src and connect-src both need it or the widget silently breaks.
- There's a twin handler at netlify/functions/chat.mts mirroring api/chat.ts — any real Turnstile patch has to land in both or Netlify deploys stay unprotected.
- OpenRouter free ':free' models: 20 req/min and 50 req/day per account if lifetime credit purchased is under $10; 1000 req/day if $10+ has ever been purchased. Limit is enforced globally per account — creating extra API keys or accounts does not raise it (OpenRouter's own words: 'we govern capacity globally').
- The docs did not state whether failed/errored requests still consume the daily quota — worth treating as 'assume yes' for planning purposes since OpenRouter did not rule it out.
- @react-three/postprocessing's own node_modules/maath (547K nested copy) is already counted inside its 897K du total, but the top-level node_modules/maath stays regardless because @react-three/drei also depends on maath ^0.10.8 — don't count that one as reclaimed.
- @paper-design/shaders-react pulls in a sibling @paper-design/shaders (1.1M) as a transitive dep that isn't in package.json directly — npm uninstall will prune it too since nothing else references it, so it belongs in the reclaim total.
- scripts/qa/bundle.mjs already has a BANNED list keeping @paper-design/shaders-react out of Dashboard/Chapter/Subjects/Master bundles specifically — that's a QA guard against the package leaking into those routes, not evidence it's used; worth knowing so nobody mistakes that grep hit for a real import.
