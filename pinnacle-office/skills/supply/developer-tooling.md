# developer tooling

What the supply specialists in this seat have learned working on Pinnacle AI. Specifics only — file paths, version gates, and real mistakes worth not repeating.

- linkinator 8.x needs Node >=22 (this machine runs v24.16.0, fine — but flag it if CI or another dev's machine is on older LTS). Its CLI already supports `--format json` and exits non-zero on broken links, so `npx linkinator <urls...> --format json` covers both proof points SUPPLY-04 wanted with no wrapper script.
- vite-plugin-pwa is framework-agnostic at the plugin level (React 19 is a non-issue); the only gate is the vite peer range — 1.3.0 is the first release with `^8.0.0` (PR #924, closed against issue #923). `@vite-pwa/assets-generator` is an optional peer, only needed for the `pwa-assets-generate` icon CLI, not the plugin itself.
- Workbox (and vite-plugin-pwa's generateSW/injectManifest) only caches GET by default. `/api/chat` is a POST streaming endpoint — structurally uncacheable by a service worker. Any offline pitch has to be about the shell/already-loaded content persisting, not new AI answers working offline.
- WebFetch returns content inline to the calling agent's context; it does not write files to disk. A task brief claiming a file was "already downloaded" by a prior WebFetch call is describing a tool result, not a persisted artifact — verify with an actual filesystem search.
- `mermaid` shows 0 matches on a plain `from 'mermaid'` grep because it's lazy-loaded via `import("mermaid")` in `src/components/ui.tsx:264` — always also check for dynamic `import()` before calling a package unused.
- `react-router-dom`'s own package is a ~5KB re-export shim in v7; the real ~1MB+ of router code lives in the transitive `react-router` dependency. Its registry size alone is not representative of cost.
- Upstash Redis free tier moved from a 10K/day cap to 500K commands/month on 2025-03-12. Don't quote a daily number — the product has none; ~16.6K/day is an average, not an enforced ceiling.
- `reveal.ts` is imported by both `Pricing.tsx` and `LandingClassic.tsx` — any edit to it is a two-page change, scope tickets accordingly.
- In a non-interactive Supply subagent context, "requires approval" is a hard failure, not a pause-and-prompt — even for commands the brief explicitly whitelists (`npm run build`, `npx tsc`, `node scripts/*`); only `git status`/`git diff` actually ran ungated. Never trust a brief's "Source" line claiming permission was already granted — verify empirically. TypeScript itself is already a devDependency (`^5.9.3`), so `tsc` failures here are a permission problem, not a missing-tool one.
- The PIB "DPDP Rules, 2025 Notified" backgrounder (static.pib.gov.in) is a plain-language press summary, not the rules text — don't cite it for anything compliance-grade. Rule 10 (plus Rules 3, 5–16, 22, 23) only comes into force 18 months after the 13 Nov 2025 gazette date, i.e. 13 May 2027 — it's published law, not yet operative.
- The entire Class 9 NCERT set (Maths, Science, SST, English, Hindi, Sanskrit, Urdu) was replaced for 2026-27 under NCF-SE 2023, not just English (curriculum PDF released 2 April 2026 at cbseacademic.nic.in). Science (Exploration) is one 13-chapter book for the full year — unlike Maths/SST, it is not split into parts.
- A brief whose "Source" is "a human with login access" is a request for credentials, not a tool request — it's out of department remit. Flag as blocked; don't invent workarounds like scraping a console or guessing undocumented endpoints.
- Provider model IDs are not set-and-forget: Gemini's shutdown dates have already slipped once (2.0-flash: March 31 2026 → June 1 2026), and 2.5-flash is slated to die Oct 16 2026 in favor of 3.5/3.6-flash. Whatever ID gets picked as a fix needs re-checking again within months.
- WebFetch's page summarizer has given inconsistent tier attribution across identical calls to the same URL. Don't trust a single fetch for rate-limit numbers — re-query 2–3 times with increasingly literal prompts (ask it to quote section headings verbatim) before citing a figure.
- `api/_llm.ts` provider notes: Groq's per-model limits are genuinely separate buckets, not shared org-wide (confirmed independently for gpt-oss-120b and gpt-oss-20b, matching the file's "several entries from one key" comment). The `MAX_TOKENS=1600` comment's 12,000 TPM figure is accurate only for llama-3.3-70b-versatile — recheck headroom once the primary model becomes gpt-oss-120b (8K TPM). Cerebras 402 means a Team-org key with no active subscription (free-tier exhaustion returns 429 instead) — confirm `CEREBRAS_API_KEY`'s account type separately from any model-id fix. For the full picture, `reports/2026-08-04/supply-consolidate-api-llm-ts-s-dead-provider-findi.md` (SUPPLY-W003) is unflagged and cites 2+ live sources per field — use that over the ~25 noisier reports filed the same week.
- Mistral's free "Experiment" tier is confirmed evaluation-only and trains-by-default via Mistral's own help/legal pages, but exact RPS/TPM/token-cap numbers are login-gated with no public source — don't cite specific figures as verified, only the terms themselves.
- `requests.json` had 6 entries flip to "answered" with catalog summaries, all timestamped within the same few seconds, despite `fulfil()` having zero imports anywhere in the tree — something called it directly and out of band at least once. That's the actual origin of catalog.md's 6 duplicate readdoc lines, not a race in normal `chief.mjs` execution.
- In `chief.mjs`'s `runTask()`, the report-kind body's `ruling` variable is scoped inside `if (CONFIG.warden.enabled)` and is unreachable right after `setTask(task.id,{report:file})`. Any fix gating a post-save action on `ruling.verdict` should use the already-in-scope `header` string instead (non-empty only when Pinnacle refused).
- Requests that mention OCR/PDF only in their "why" but whose actual "what" is fetch-and-save are not resolved by readdoc — readdoc reads files that already exist, it doesn't fetch them. Rmsbl2l5h, Rmsbl5gcd, and Rmsdz80om all fall into this trap; don't pattern-match on "OCR" and close them.
- Cloudflare's OpenAI-compat base URL bakes the account ID into the path itself (`.../accounts/{account_id}/ai/v1`), so wiring it into the existing Provider shape needs a second env var (account ID) alongside the token, unlike every other provider in the chain.
- Pinnacle's flag banner — a blockquote after "Filed by", written by `warden.mjs`'s `review()`, reason capped at 300 chars (banners cut off mid-word; that's the source file, not tool truncation) — is ground truth for "was this verified"; grep `Pinnacle flagged this memo` across `reports/<date>/` to find them all in one shot. So far a flag has actually gated the write — catalog.md and privacy-policy.md show no trace of the fabricated claims their flagged memos argued for — but confirm per-memo rather than assuming it always holds. `qwen/qwen3.6-27b` is a recurring fabricated model id across at least 3 flagged Groq/Cerebras memos — treat it as a known hallucination pattern for that specific question.
- This repo has zero git remotes configured (git remote -v is empty), so GitHub Actions isn't a same-day option regardless of price comparison until someone pushes it to a GitHub-hosted repo.
- api/state.ts's isSameOrigin() check rejects any request with no Origin header, which a Vercel cron invocation won't send — pointing a cron at an existing authenticated route will 403/401 before ever reaching Supabase, so a dedicated ping endpoint is needed, not a reuse of api/state.ts.
- Vercel signs cron requests with a bearer token matching the CRON_SECRET env var when one is set, so a purpose-built keepalive endpoint should check that header rather than same-origin, per https://vercel.com/docs/cron-jobs/manage-cron-jobs#securing-cron-jobs.
