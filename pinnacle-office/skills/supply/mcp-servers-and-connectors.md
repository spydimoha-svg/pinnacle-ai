# MCP servers and connectors

What the supply specialists in this seat have learned working on Pinnacle AI. This file is not really about MCP servers — it's the seat's dumping ground for real, codebase-specific lessons — so it's organized by subsystem, not by topic.

- CBSE publishes no standing "added/deleted chapters" doc — diff this year's subject PDF against last year's. The curriculum page URL shifts by the session's *end* year (2026-27 → curriculum_2027.html, 2027-28 → curriculum_2028.html); don't hardcode it, follow the current-year "Curriculum" nav link from cbseacademic.nic.in instead.
- 2026-27 is a full NCF-2023 rollout (circular Acad-14/2026): new NCERT textbooks for Class 9 cascading through 10-12, plus mandatory third language from Class 9. The four files in src/data/curriculum (class9-12.ts) were still pinned to 2025-26 and need a full re-sync, not a patch.
- cloud.ts's Supabase path only runs under `npx vercel dev` (api/state.ts is a Vercel Function) — plain `vite dev` won't exercise it. cloud.ts reads `import.meta.env.VITE_SUPABASE_URL` (Vite-only), so it must be loaded via `vite.ssrLoadModule`, not plain node/tsx, same as store.ts in scripts/qa/sync.mjs; its exported saveUserData/loadUserData handle the Supabase Auth dance internally, so parity tests just call those two with a disposable email/password. supabase/schema.sql runs unmodified against a local stack (`npx supabase db reset` or Studio at 127.0.0.1:54323) and, being real Postgres with RLS, actually proves the student_state lockout (no anon/authenticated policy) locally rather than just asserting it.
- onnxruntime-node alone is 258MB unpacked, already over Vercel's 250MB standard function bundle limit before any model file — Kokoro/piper-plus paired with it is dead on Hobby. onnxruntime-web (WASM) is ~94MB but ships every wasm variant; fitting an 86MB model under 250MB needs manual vercel.json includeFiles/excludeFiles trimming, untested here.
- Vercel Hobby: ToS restricts it to non-commercial personal use — a standing risk for a parent-paid product, confirm actual plan tier. Its cron feature is free but capped at once/day (fails at deploy time, not a silent degrade) and only fires on production deploys via the vercel.json crons block; delivery is best-effort (can double-fire or skip), so whatever endpoint it hits must be idempotent.
- Chrome on Android's `speechSynthesis.getVoices()` returns an unfiltered language/region list, not actually-installed voices — a "hi" match can appear present but not be downloaded (Chromium bug 331977824). Not fixable from src/lib/speech.ts alone; Android's Hindi voice pack isn't preloaded unless it's the UI language or "popular."
- No git remote is configured at the repo root — any CI workflow needs a push first. No `engines` field or `.nvmrc` anywhere — pin Node 20 LTS explicitly in any new workflow rather than assume inheritance.
- Bash requires live approval per `node` invocation even for trivial ones, despite `node scripts/*` being listed as pre-permitted for Supply. The allowlist is exact-match only (npm run build, npx tsc, node scripts/*, git diff, git status); curl and inline `node -e` are auto-denied, not just prompted.
- vitest 4.1.10 already satisfies this repo's vite ^8.1.4 and Node v24.16.0 with no TypeScript peer dependency to negotiate. The stuck adoption requests (Rmsbmrsml, Rmsbmsros) were blocked purely on Bash execution access, not on tool choice. Separately, vitest/config's defineConfig is a drop-in superset of vite's own (same shape plus `test`), so swapping the import in vite.config.ts doesn't touch existing plugins/server/build blocks — no separate vitest.config.ts needed.
- npmjs.com package pages 403 WebFetch in this sandbox — use registry.npmjs.org/\<pkg\>/latest instead when vetting package versions.
- Uptime monitoring: UptimeRobot's free tier banned commercial use from Dec 2024; Freshping shut down entirely 2026-03-06 (data deleted by 2026-06-04). Better Stack is the live pick — watch the domain (betterstacks.com, with an s, is unrelated) and read its real ToS since it has only a generic "refuse service" clause, no explicit commercial restriction confirmed.
- Supabase free-project pausing needs daily-ish activity, not just weekly. Pausing freezes Postgres (no data loss, 1-year restore) but nothing in this repo currently pings it — no .github/workflows, no vercel.json crons block.
- WebFetch never exposes raw HTTP headers and securityheaders.com 403s it outright — api.hackertarget.com/httpheaders/?q=\<url\> works but is rate-limited to ~1 free query/day. Vercel already auto-sends HSTS on *.vercel.app by default, so only the other four security headers need manual work.
- Crisis helplines: Tele-MANAS (14416 / 1800-891-4416) is the primary line for exam stress, ahead of the older KIRAN number. iCall (TISS) has youth-trained counsellors but isn't 24x7 (Mon-Sat 8am-10pm) — never give it as the sole number at night. Childline 1098 still works (confirmed active June 2026) but is being folded into 112 under Mission Vatsalya — revisit yearly, same discipline as the curriculum URLs.
- TOOLS.build in claude.mjs already has the exact commands (npm run build, npx tsc:*, node scripts:*) for `dept.kind === 'code'` departments in apply mode (config.mjs) — mirror these existing pattern strings rather than inventing new ones.
- .gitignore's `*.local` rule does not match `settings.local.json` (it doesn't literally end in `.local`) — a personal .claude/settings.local.json needs an explicit .gitignore line or it will get committed.
- pinnacle-office/core/ and pinnacle-office/config.mjs are both in config.mjs's own forbidden[] array — even a code-writing department with Edit access would have its change to core/claude.mjs auto-reverted by the gate. This is a structural block enforced by the same git-revert mechanism that protects everything else in forbidden[].
- GitHub's changelog page filtered by the 'models' label (github.blog/changelog/label/models/) returns empty via WebFetch even though individual dated changelog URLs work fine fetched directly — search first to find the exact post URL rather than trusting the label-filtered index.
- Third-party aggregator sites (getaitools.dev, freellm.net, getfreeai.net, pecollective.com) still serve stale pre-retirement GitHub Models rate-limit numbers (150 req/day for mini models, 8K in/4K out) as current with no retirement notice — cross-check github.blog directly, don't trust these.
- ncert.nic.in/textbook/pdf/\<code\>ps.pdf is the prelims file for an NCERT title (front matter, credits, full Contents page with page numbers) — a much smaller, faster download than the per-chapter PDFs for getting an authoritative chapter list. The Kaveri code prefix in NCERT's URL scheme is 'iebe1' (grade 9 English); other-subject Kaveri-equivalents likely follow the same iebe-style naming, worth trying first before searching.
- Official Indian gov sites routinely 403 WebFetch outright (meity.gov.in on every path, indiacode.nic.in, pib.gov.in's PressReleasePage.aspx/PressNoteDetails.aspx) — a bot/WAF block, not a cert issue. Workarounds: static file-serving subdomains often aren't blocked (static.pib.gov.in works); WebFetch also silently caches the raw PDF binary locally even when it fails to extract text ("font/encoding" errors) — the cached path is in the error output, pipe it through readdoc for clean paginated text. dpdpa.com/DPDP_Rules_2025_English_only.pdf is a verbatim gazette republish (titled "GAZETTE OF INDIA," carries G.S.R. 846(E)), usable as a stand-in despite the non-.gov.in domain.
- docs.mistral.ai/deployment/laplateforme/tier and /deployment/ai-studio/tier both 404 now (renamed to docs.mistral.ai/admin/user-management-finops/tier), but even the working page deliberately withholds numbers and defers to the authenticated admin console — this is Mistral's design choice, not a docs gap to work around.
- help.mistral.ai and legal.mistral.ai are NOT behind auth and both directly answer the evaluation-only and training-default questions in plain language — check these before assuming something needs a logged-in account.
- legal.mistral.ai/terms/commercial-terms-of-service Section 4.2 is the actual contractual source for the training-default claim, stronger than help-center prose if this ever needs citing to a parent or in a DPDP compliance note.
- console.groq.com/docs/rate-limits and console.groq.com/docs/deprecations are the authoritative source for Groq TPM figures and worked fine via WebFetch — no need to fall back to the flagged-unreliable third-party aggregator sites (tokenmix.ai, tickerr.ai etc.) which returned inconsistent numbers (6K vs 12K vs 30K TPM) for the same model in a plain WebSearch.
- The GitHub advisories page for the vitejs/vite-plugin-react repo lists 8 advisories but every single one affects @vitejs/plugin-rsc (react-server-dom-webpack RCE/DoS chain), not @vitejs/plugin-react — don't let the shared repo fool a quick read into flagging the wrong package.
- Vite has had 4 CVEs disclosed in 2026 alone (39363, 39364, 39365, all High/Moderate in April; 53571 in June, Windows-specific fs.deny bypass via NTFS ADS/8.3 short names) — all dev-server-only, all fixed by 8.0.5 or 8.0.16, and this repo's 8.1.4 already sits above every fix version. Worth re-checking on the next Vite bump since this package clearly gets frequent dev-server security findings.
- GitHub's advisories search UI (github.com/advisories?query=...) is more reliable for exact-package filtering than WebSearch, which surfaces third-party CVE aggregator noise; go there directly for these checks.
- package.json's caret-pinned version can be wildly stale vs what's actually in node_modules — always read node_modules/<pkg>/package.json for the real installed version before vetting advisories, not the semver range in package.json. Here @supabase/supabase-js said ^2.47.10 in package.json but 2.110.7 was actually installed.
