# free tier APIs

What the supply specialists in this seat have learned working on Pinnacle AI, a CBSE tutoring web app built on free-tier LLM APIs and free/open tooling. Written for whoever picks up this seat next, not for the record.

- The two hand-built chapters in src/data/ncert (paraphrased 'concepts' text + short factual problem statements + originally-written solutions) are the only defensible sourcing pattern for NCERT content — it doesn't scale via bulk import, and most 'NCERT solutions' sites (Vedantu, LearnCBSE, GeeksforGeeks, GitHub scrapes) are themselves unlicensed reproductions NCERT explicitly warned about in a mid-2026 press release. Don't launder their copy as a shortcut.
- There is no manualChunks in vite.config.ts — all splitting is React.lazy() route boundaries plus one hand-written dynamic import('three') inside useShaderQuad.ts, which is why the landing page's chunk references three.module.js but never loads it eagerly.
- package.json dependencies do not equal bundle weight — always grep src/ for the actual import before charging a package as cost. @paper-design/shaders-react and @react-three/postprocessing are both installed and both unused.
- @react-three/postprocessing is the sole non-transitive parent of postprocessing, n8ao, maath, and its own nested maath@0.6.0 copy (drei wants the hoisted maath@^0.10.8) — uninstalling it alone reclaims all ~5.3M with nothing left over. The only other hits for these names are design-authority.js/design-council.js listing them as 'verified free and allowed' in prompt text, not real usage.
- dist/ is regenerated by something outside this conversation — route-level chunk hashes rotate mid-session while vendor chunk hashes/sizes stay byte-for-byte identical. Treat that vendor-chunk stability as the freshness signal, not file mtime.
- curl is not on this seat's Bash allowlist and fails with 'requires approval' every time it's tried, regardless of curl.exe being physically present (System32, Git-for-Windows Bash). Use WebFetch for live URL checks; for anything curl-shaped that WebFetch can't do, Node's built-in https/tls module is the real path once the script-approval gate is dealt with (see below).
- If a fix ever needs a custom CA (e.g. adding a cert via tls's `ca` option), remember it REPLACES Node's default trust store rather than extending it — spread tls.rootCertificates alongside any custom pem or every other HTTPS site becomes untrusted for that request.
- node scripts/* is nominally allowlisted but reliably fails 'requires approval' in a non-interactive subagent context (reproduced repeatedly), and TOOLS.survey (chief.mjs:122) grants Bash(node --version) but not Bash(node scripts:*) either — no backdoor there. But SUPPLY-W014 showed WebFetch/WebSearch work fine at top-level despite being denied in a subagent, so this may just be a subagent-context restriction, not categorically dead — retest from a top-level Supply session before writing it off again.
- cbseacademic.nic.in's WebFetch responses are reliable enough to quote circular titles verbatim. cbse.gov.in (a different domain) returns HTTP 403 to WebFetch site-wide including its homepage — that's not evidence the target page is down; confirm cbse.gov.in URLs via WebSearch exact-URL quoted search instead.
- The year-shift URL convention (2026-27 session → curriculum_2027.html) is confirmed real via the CBSE homepage nav, not a guess — safe to hardcode or navigate by nav link for this session.
- class10.ts has zero year marker anywhere (grep for 2025-26 returns nothing) — a resync should add one, not assume it matches class9's comment style.
- Groq deprecated meta-llama/llama-4-scout-17b-16e-instruct on 2026-07-17 with no vision replacement; current free lineup (gpt-oss-20b/120b, llama-3.3-70b, llama-3.1-8b, qwen3.6-27b) has no vision-capable model. Re-check console.groq.com/docs/models before recommending Groq for vision — they rotate fast.
- Google cut Gemini free-tier quotas 50-80% in December 2025; gemini-2.5-flash free tier is now 10 RPM / 250 RPD / 250K TPM. Thin margin for stacking it as a second free-tier lane.
- gemini-2.0-flash — hardcoded as DEFAULT_MODEL.gemini in api/_llm.ts — is deprecated and shut down. Any request routed to Gemini today hits a dead model name unless GEMINI_MODEL env var overrides it. Plain bug, worth its own fix task.
- WebFetch against openrouter.ai/api/v1/models truncates/samples and under-reports the free-model catalog (once returned only 6 :free entries, missing e.g. llama-3.2-11b-vision-instruct:free). Cross-check a specific model's own openrouter.ai/<id> page before concluding it doesn't exist.
- Git for Windows ships standalone pdftotext.exe but not the rest of poppler-utils (no pdftoppm/pdfimages) — and it wouldn't help with CBSE circulars anyway since pdftotext only pulls an existing text layer, and those PDFs have none.
- pdf-to-png-converter depends on @napi-rs/canvas (not classic node-canvas), which ships prebuilt native binaries per platform — works on a Windows box with no Cairo/node-gyp/Visual Studio build chain.
- tesseract.js v7 needs Node 16+ (fine, this machine runs v24.16.0) and by default fetches its WASM core and language data (e.g. eng.traineddata) from a CDN at first run — pass explicit corePath/workerPath/langPath under node_modules for offline use.
- The real gap in getting a remote PDF processed isn't any single tool's capability — Read's file_path is local-filesystem-only (no URL fetch), WebFetch is read-only with no side-channel to persist bytes to disk, and Read already documents full multimodal PDF support (page ranges, 20-page cap) once a file exists locally. The missing piece is always "how does the PDF get onto disk," not "can something read it."
- task.requestId is written once, at raise time, in raiseRequests() (chief.mjs:153), and never read again anywhere in the repo — it's the exact join key fulfil() needs to close the loop, already sitting on disk for every queued/done Supply task.
- approve()/decline()/openRequests() are already fully wired (imported server.mjs:14, bound to approveTool/declineTool UI commands at server.mjs:430-438, backing /api/supply and the dashboard supplyOpen count) — they just never fire because no request ever leaves status 'open' to become 'answered'. The fix is upstream of these functions, not in them.
- Before answering 'can X be done', check dept.kind for whoever actually needs to run it — a technically correct answer is still a non-answer if the requesting department can never execute it.
- openrouter.ai/api/v1/models truncates before reaching llama-3.3-70b-instruct:free in a WebFetch call (confirmed again today, matches the standing memory note) — a 'not found in the live JSON' claim from that endpoint is not evidence of removal, it's evidence of truncation. The model's own dedicated page (openrouter.ai/<id>) is the source that actually renders its current status.
- requests.json has no dedup or full-text check before an agent files a new entry, and answered entries (see Rmsbkbdtp, Rmsdtqgqb, etc.) only get marked once someone manually edits the file — nothing in the workflow surfaces 'this exact problem was already filed 5 times' to the 6th agent before it types out request 6.
- Live-testing this from inside my own Supply session got an immediate synchronous error ('This command requires approval'), not an actual indefinite hang. Whoever named the bug 'hangs' most likely means 'the agent keeps hitting this wall every turn and never makes progress within its timeout', not a literal blocked-forever prompt.
- class9.ts has no Hindi, Sanskrit or Urdu subject object at all (grep for those three names in the file returns zero hits) — CLASS_9_SUBJECTS only lists maths, science, sst, english. The task framing implied these three subjects exist and might 'differ'; in reality there's nothing there to compare, so Content is authoring three subjects from scratch, not revising them.
- Same for SST: the four-book History/Geography/Political-Science/Economics structure in class9.ts (French Revolution, India Size and Location, What is Democracy, Village Palampur, etc.) is replaced by a differently organised two-part book, 'Understanding Society: India and Beyond' — chapter mapping is not 1:1, so this needs a fresh table of contents, not a title swap.
- The Kaveri book code is 'iebe1' and NCERT's per-chapter PDFs follow the pattern ncert.nic.in/textbook/pdf/iebe1{NN}.pdf (e.g. iebe101.pdf for chapter 1), with iebe1ps.pdf being the prelims file that contains the front matter and full contents page — fetch that one file for the whole table of contents instead of guessing chapter numbers one at a time.
- WebFetch cannot read PDF binary content directly (returns 'binary content... unable to extract'), but it does save the PDF to a local tool-results path, and the office's readdoc tool then reads it cleanly with page markers — this two-step (WebFetch then readdoc) is the working path for any ncert.nic.in PDF, not just this one.
- Kaveri's contents page numbers each prose piece (1 through 8) but leaves poems unnumbered under their paired prose entry, e.g. '1. How I Taught My Grandmother to Read' followed by 'Bharat Our Land' with no number — a chapter list schema keyed on Unit N should treat prose+poem as one unit, not two separate numbered chapters.
- The task brief cited chief.mjs:118-119 for the TOOLS.build grant; in the current file that's dept-loop cleanup code (emit("plan.done", ...)) — the actual grant is toolsFor() at chief.mjs:124-131, specifically line 125. Line numbers drift fast in this file; always re-grep before citing.
- catalog() in supply.mjs takes zero arguments and is called with no dept/mode context (chief.mjs:245), so BASE is baked once and handed to every agent identically regardless of dept.kind or office.mode — a text-only fix can be honest but can't be *this agent's* Bash set specifically without also threading dept/isCodeWrite into catalog()/workerBrief.
- office.mode is 'apply' or 'propose' (server.mjs:364), not 'apply' or 'plan' as the variable naming suggests — even a dept.kind:'code' agent gets no Bash build tools while the office is in propose mode.
- The contents page prints unit numbers only on the prose piece (e.g. '1. How I Taught My Grandmother to Read'); the paired poem is the very next line with no number (e.g. 'Bharat Our Land') and a later page number in the same unit's range, confirming the free-tier-apis.md note that Unit N = one prose + one poem, not two chapters.
