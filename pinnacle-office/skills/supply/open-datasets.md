# open datasets

What the supply specialists in this seat have learned working on Pinnacle AI.

- resources.ts: 8 unique URLs behind ~33 entries (NCERT_TEXTBOOKS, NCERT_EXEMPLAR, CBSE_SQP_X/XII, CBSE_CURRICULUM, CBSE_PYQ, DIKSHA, CBSE_QBANK) — dead-link checks here are an 8-URL problem, not a 33-entry one.
- scripts/qa.mjs's run.ts is a live-chat probe auditor (hits /api/chat, judges tutor answers) — a separate concern from static link validation; it belongs as a sibling script alongside qa:figures/qa:lesson/qa:video, not folded into run.ts's loop.
- DigiLocker requires a security audit (STQC/CERT-In empanelled or equivalent) before production API access, billed separately from the platform — the free-tier story breaks at the production gate, not registration.
- The government Requester API (apisetu.gov.in) is a document-fetch/eKYC flow keyed to whoever completes the Aadhaar OTP at that moment — it has no 'parent of student X' concept; that relationship has to live in Pinnacle's own data model.
- Primary-source PDFs from digilocker.gov.in and cf-media.api-setu.in return corrupted/unparseable to WebFetch — needs a human to open them directly, or a PDF tool outside this office's toolset.
- WebFetch never writes files to disk in this harness — verify a file actually exists on the filesystem before assuming a prior agent "downloaded" it.
- OCR pipeline: node-tesseract-ocr needs a separately-installed system tesseract.exe on PATH and has a published OS command-injection CVE in recognize() — rejected on both grounds. tesseract.js + @napi-rs/canvas-backed converters (pdf-to-png-converter, pdf-to-img) are the pick instead: they ship prebuilt win32-x64-msvc binaries and skip node-gyp, unlike plain `canvas` which needs VS Build Tools on Windows.
- Read renders a PDF page as an image and a vision-capable model reads the text off it — that already functions as OCR for any page Read can open. tesseract.js is only needed as a fallback for pages Read's own renderer can't parse.
- Task briefs like "Bash, but only: npm run build, node scripts/*" are documentation only — Claude Code's permission engine only reads permissions.allow/deny/ask arrays in settings.json; empty arrays mean every listed command still prompts.
- settings.local.json is gitignored and machine-personal — an office-wide permission fix belongs in the committed .claude/settings.json, not there.
- .claude/settings.json currently only carries the env-key-blanking block (Rule 1) — the Bash permissions.allow block drafted for the node scripts/npm run build/npx tsc gridlock was never added; that cluster is still genuinely open, not fixed-but-unapplied.
- Even with permissions.allow added, core/claude.mjs's runAgent() spawns every office subagent with --setting-sources "", making any committed settings.json invisible to those runs — the real lever is TOOLS.build/TOOLS.survey inside core/claude.mjs, which sits on Supply's forbidden-edit-paths list.
- This interactive session auto-declines both `node -e "..."` and `node scripts/<file>.mjs` identically with "This command requires approval" and no answerable prompt — the block applies to Node execution as a class, not to any specific syntax.
- This repo has no git remote (`gh repo view` returns "no git remotes found") — the Dependabot question is unanswerable, there's no GitHub repo to enable it on yet. Separately, package.json's "private": true is npm's own accidental-publish guard and has no bearing on GitHub visibility — don't read it as evidence either way.
- requests.json's entry count goes stale mid-session (grew 24→26 while a task was already in flight) — re-grep the id count rather than trust a cited number.
- egazette.gov.in's missing chain is two certs, not one — YR2 (int-yr2.pem) and Root YR (root-yr.pem), both needed to bridge its leaf cert to ISRG Root X1; a predecessor ticket said "one" cert, but the actual gen-y hierarchy has an extra hop. Because execution stayed blocked, this fix is diagnosed and its materials identified but not proven end-to-end — don't report it solved until an agent with real Node execution completes the handshake.
- OpenRouter's /models browsing page is client-side rendered (Next.js) — WebFetch only sees the nav/header shell, not the model table. Use the raw API JSON or individual model pages instead.
- Groq's deprecations page kills llama-3.3-70b-versatile AND llama-3.1-8b-instant on the same day (2026-08-16) — GROQ_FALLBACK_MODELS' current default silently degrades to a single working model that day, not two.
- qwen/qwen3.6-27b is a real, currently-listed Groq model (has its own docs page) despite the version number looking like a WebFetch hallucination — worth a second look before dismissing an oddly-named model ID.
- supabase/cli on GitHub is MIT, not Apache-2.0 (confirmed by fetching the repo page directly). Its docs require Node 20+ via npx/npm and this repo pins no engines field, so check `node -v` first. `npx supabase start` pulls Docker images on first run — a one-time cost, not a hang.
- supabase/schema.sql's RLS revokes ALL grants from anon/authenticated on student_state, schools, and school_resources — a local test only proves anything if it uses the service_role key the way api/state.ts and api/chat.ts do in production; testing via the anon key produces false permission-denied negatives unrelated to the code path being tested.
- WebFetch runs pages through a summarizing model by default and will silently paraphrase license text — demand a verbatim quoted excerpt explicitly when confirming exact legal wording. Also: unpkg's bare directory-listing URL 301-redirects to app.unpkg.com, so fetch the redirected URL directly; and file size is a cheap independent signal (installed LICENSE at 11.4 kB matches Apache-2.0's ~11.3 kB, while PolyForm Shield 1.0.0 runs ~5-6 kB) that can catch a mislabeled license before reading a word of content.
- Pausing is not deletion: data and config are preserved, and there's a 1-year window to manually restore via Supabase Studio (Resume project button) before backups age out and restoration is no longer offered.
- The docs explicitly say 'making API calls to your project or sending requests via your connected application' counts as activity that prevents pausing — meaning any real user traffic through api/state.ts or api/chat.ts already resets the clock; the exposure is specifically a period with literally zero visitors, e.g. a multi-week board-exam-adjacent school holiday.
- The dedup that already exists (requestTool's key() match on the 'what' text) only prevents duplicate *requests* for literally-reworded asks of the same thing; it does nothing for fulfil(), which is a separate, unguarded write path. A fix at requestTool would not have caught this, because these six 'what' strings were genuinely different English, they just converged on the same answer.
